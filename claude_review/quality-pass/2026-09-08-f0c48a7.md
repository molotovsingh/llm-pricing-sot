## Evidence & fixes

| Unit | Verdict — judgment · where (`file:line`) · Fix |
|---|---|
| `_query_review` | ⚠️ **The review work list does not know the second truth layer exists.** `fetch_pricing.py:1294-1306` walks `needs_review`, looks each id up in `ctx.models` and `load_overrides`, and when neither hits — which is *every* deployment id — falls to the default reason `"dropped-unpriceable"` with `declared_in/out: None`. Verified: a deployment flagged `gpu-rate-missing` is reported as dropped-unpriceable. This is the surface a human uses to decide what to fix, and for the new layer it reports a reason that is false and a declared price that is blank. It shipped because `needs_review` was widened to hold deployment ids (`run()`, `:790-793`) without widening the one consumer that interprets them. **Fix:** in `_query_review`, resolve each id against `cache["deployments"]` first: reason from `entry["review"]`, declared price from `load_deployments(ctx.deployments_path)` in the unit's own fields, serving price from the emitted entry; only fall back to the model path when the id is not a deployment. Add a test that flags one deployment and asserts the row's `reason`. |
| `_query_price` without `--host` | ⚠️ **A model that exists only as a deployment is invisible unless the caller already knows to ask for a host.** `fetch_pricing.py:1335-1372`: the resolution order is tracked model → discovery baseline → not found; `ctx.deployments_for(model)` is consulted only inside the `--host` branch. Verified: `price vendor/OCR` → exit 2, `price vendor/OCR --host replicate` → the price. The self-hosted OCR model — the reason the layer was built — cannot be priced by the plain question. **Fix:** before the discovery fallback, if `deployments_for(model)` is non-empty: serve it when there is exactly one, and when there are several return `found: false` *with* a `deployments: [ids]` field so the caller learns which `--host` to ask for. Either way, never a bare not-found while a deployment exists. |
| `run()` cache-hit path | ⚠️ **Editing the truth files does nothing until the cache goes stale.** `fetch_pricing.py:826-838` serves a fresh cache with zero work and re-reports its stored `needs_review`; deployments are resolved only on the refresh path (`:781-793`). Verified: delete every deployment, re-run — both are still emitted and exit stays 1, and will for up to `DEFAULT_TTL_HOURS` (168). This was *always* true of `overrides.json`, but the refit made hand-edited truth files the primary thing a user touches, so latency that was a footnote is now load-bearing: the documented remedy for a flagged deployment is "fix the file", and the file has no effect. **Fix:** stamp a fingerprint of the three truth files into the envelope (`truth_hash`, e.g. sha256 over their bytes) and have `run()` take the refresh path when the current fingerprint differs — a data edit is a staleness event. The envelope gains one key; the gate regenerates six documents; `is_fresh` (age) stays untouched. Cheaper interim: `query deployments` and `review` print a one-line notice when the files are newer than `fetched_at`. |
| `host_rows` · cross-check freshness | ✅⚠️ **The verifier never says how old its evidence is.** `host_rows` (`:687-727`) reads the endpoint snapshot on disk and emits rows with no `fetched_at`; `resolve_deployments` (`:739-802`) attaches such a row as `catalog` during `run()` without refreshing the snapshot even when online. ## Emerging themes

- **T4 — The second truth layer is half-plumbed into the query surface.** Two consumers
  of the widened data model were not widened with it: `_query_review` (reads
  `needs_review` ids, only knows models) and `_query_price` (only knows deployments
  when told a host). Both are the same omission — the data was added at the bottom
  and the surfaces that *interpret* it at the top were left assuming the old shape.
  The `67bfe98` review missed both because it verified the new surfaces
  (`hosts`, `--host`, `deployments`) and never re-probed the old ones with the new
  data. **Lesson for the next refit:** enumerate every reader of a field you widen.
- **T5 — Staleness is measured by age of the cache, not by change in the truth.**
  Two units expose it: the cache-hit path ignores truth-file edits, and the cross-check
  ignores snapshot age. The repo has one freshness concept (`fetched_at` + TTL on the
  envelope) and now two more things that can go stale independently — the truth files
  (by edit) and the per-host snapshots (by age). A fingerprint of the truth files and a
  `fetched_at` on catalog rows would give each its own signal.

**Meta-observation.** The refit's core — resolution, derivation, validation, the trust
rules — held under hostile input. The defects are all at **the seam between the new
layer and the surfaces that predate it**: the work list, the plain `price` question,
the freshness model. That is where a self-review is weakest, because the author
tests what they built and not what they changed the meaning of. It is also the
cheapest place to fix: three functions, no new abstractions.
